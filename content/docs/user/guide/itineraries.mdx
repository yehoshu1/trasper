---
title: Itineraries
description: Quotation-linked and standalone itineraries, reissues, previews and PDFs.
---

An itinerary is a frozen travel document. It can come from an accepted quotation, or stand alone with
no quotation, prices or pro forma.

## Quotation-linked itinerary

Requirements:

- the quotation is **accepted**;
- at least one journey exists and has flights;
- the user has the `manageDocuments` capability.

The itinerary copies every journey's flights, passengers, PNR and reference into a snapshot, with the
standard itinerary notes. Multi-journey quotations print one section per journey. It is issued from
the quotation page. A second itinerary for the same quotation supersedes the first; the old document
remains available for history.

## Standalone itinerary

Use **Itineraries → New standalone itinerary** when no quotation or price is involved.

Fields:

| Field | Notes |
| --- | --- |
| Customer | Required, active customer. |
| Reference | Optional customer or booking reference. |
| Booking reference (PNR) | Optional short record locator printed on the document. |
| Issue branch | Two digits, used in the itinerary number. |
| Flights | Add segments by hand with **+ Add flight** — airline, flight number, airports and local times. At least one flight is required unless pasted text is supplied. |
| Import a PNR or itinerary | Always visible. Paste booking-system output or itinerary lines and choose **Read / convert** to apply the flights to the rows above. Parsed deterministically and never guessed. |
| Passengers | Optional selection from the passenger list. |
| Travel notes | Blank uses the standard itinerary notes. |

Either the manual flight rows or the pasted text must produce at least one segment. **Read /
convert** fills the flight rows for review before the itinerary is created; submitting pasted text
without converting it also works. Adding the flights by hand is the path for an itinerary that has
no booking text yet.

The standalone snapshot has its own contact, passengers and flights. It has no quotation, option,
prices, payments or pro forma. It cannot be converted into a quotation later; create a quotation if
pricing is needed.

## Reissue

**Reissue** creates a new itinerary with a new number, copies the current data, and marks the old
document `superseded`. A linked itinerary can be reissued only while its quotation is still
accepted. A standalone itinerary is reissued from its own frozen snapshot.

## Delete

An administrator can permanently delete an itinerary from its detail page. The number is not reused,
and the linked quotation is left unchanged. The deletion is audited; delete only a document that was
issued in error, because an issued itinerary cannot otherwise be reconstructed.

## Customer fields

The printed document includes the customer's name, attention line, address, city, country, email and
phone, plus the travellers and the flight table. Flight times are local wall-clock values at each
airport; durations and layovers are calculated with IANA time zones through Luxon.

## Preview and PDF

The on-screen preview and `/api/pdf/itinerary/[id]` render the same frozen snapshot. The PDF is
produced with `pdf-lib`; no headless browser is required at runtime. Users need `viewDocuments` to
download a document.

## What is frozen

- company identity, logo/letterhead and footer;
- customer and passenger names;
- flights, airline names and logos;
- notes and reference;
- template choice;
- document number and issue date.

Later changes to templates, airlines, airports or company settings never alter an issued itinerary.
