## Commands

```bash
npm test          # compile and run the unit suite
npm run test:e2e  # Playwright against a production build
npm run typecheck
npm run lint
```

The unit suite is compiled with `tsconfig.test.json` into `.test-dist` and run by Node's built-in test
runner. Tests use plain `node:test`, `node:assert/strict` and table-driven cases.

## Domain rules to test

Every rule in [pricing](/docs/user/reference/pricing), [documents](/docs/user/reference/documents),
[lifecycle](/docs/user/reference/lifecycle), [permissions](/docs/user/reference/permissions) and
[PNR formats](/docs/user/reference/pnr-formats) should have an automated test. When you fix a PNR bug, add
the failing input as a fixture. When you add a pricing case, assert the line sum equals the total.

## Playwright

The browser suite covers:

- the public landing page at `/` and its sign-in/docs links;
- the `/dashboard` sign-in redirect for signed-out visitors;
- sign-in;
- customer and passenger creation and linking;
- a quotation with two options;
- send and accept;
- itinerary issue;
- pro forma issue and two-part payment;
- payment ledger entries;
- PDF download;
- agent internal pricing visibility;
- viewer denial of settings and ledger;
- a non-default bank account frozen into the PDF.

Playwright uses `npm run build && npm run start` against a scratch database. Set `E2E_BASE_URL` to
reuse an existing server. The default browser time zone is UTC; the app's agency time zone is
independent.

## Test data safety

- Never use real customer data, passport data or production dumps in tests.
- Use fixtures and neutral names.
- The smoke scripts and E2E suite are development-only.
- Reset the database with `npm run db:reset` only on a local development install.

## Time-sensitive tests

Cover at least:

- an overnight regional flight;
- a spring and autumn daylight-saving change;
- a date-line crossing where arrival is earlier in local time;
- a connection that departs before the previous flight lands.

Use IANA zone names through Luxon; never hand-write DST offsets.

## CI

CI runs install, migrate, seed, typecheck, lint, unit tests, build and a backup check on every push
and pull request. It validates that `package.json` is valid SemVer, and on a `v*` tag that the tag
matches that version. On `main` and `v*` tags it also runs Playwright, then builds the Docker image
and publishes it to GHCR. See `.github/workflows/ci.yml`.
