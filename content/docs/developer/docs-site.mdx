This documentation site uses [Fumadocs](https://fumadocs.dev) and ships inside the Trasper Next.js
application. It is public (no sign-in required) and lives at `/docs`. It is separate from the product
landing page at `/`; the docs navigation's **Open the app** link goes to the authenticated
`/dashboard`.

## Packages

| Package | Version | Role |
| --- | --- | --- |
| `fumadocs-core` | 16.x | Source loader, search server, page tree. |
| `fumadocs-ui` | 16.x | Docs layout, page shell, MDX components, prebuilt styles. |
| `fumadocs-mdx` | 15.x | MDX collection compiler and Next plugin. |

## Files

| Path | Purpose |
| --- | --- |
| `content/docs/**/*.mdx` | The documentation pages, split into `user/` and `developer/`. |
| `content/docs/**/meta.json` | Sidebar order, folder titles and root tabs. |
| `source.config.ts` | Config API collection definition (`defineDocs`). |
| `src/lib/source.ts` | Loads the generated collection with `baseUrl: "/docs"`. |
| `src/app/docs/layout.tsx` | `RootProvider`, `DocsLayout`, stylesheet link. |
| `src/app/docs/[[...slug]]/page.tsx` | Renders the selected MDX page and TOC. |
| `src/app/docs/api/search/route.ts` | Full-text search endpoint. |
| `src/mdx-components.tsx` | Shared MDX component map. |
| `src/app/docs/docs.css` | Small branding and layout bridges. |
| `scripts/sync-docs-css.mjs` | Copies Fumadocs' prebuilt CSS into `public/`. |
| `next.config.ts` | Wraps the config with `createMDX()`. |
| `tsconfig.json` | Maps `collections/*` to the generated `.source/*`. |

## Audience split

The content tree has two root folders:

```text
content/docs/
  user/          ← User guide tab
    getting-started/
    guide/
    administration/
    operations/
    reference/
  developer/     ← Developer guide tab
    architecture, code-standards, data-model, database,
    http-routes, testing, docs-site, contributing
```

`user/meta.json` and `developer/meta.json` set `"root": true`, so Fumadocs renders them as layout
tabs. The `/docs` landing page links to both audiences. Technical reference that a developer needs
(data model, HTTP routes) lives under `developer/`; behaviour that staff need (pricing, documents,
permissions, PNR formats) lives under `user/reference/`.

## Rendering

`source.getPage(slug)` returns the page; `page.data.body` is the compiled MDX component. The page
renders it inside `DocsPage`, `DocsTitle`, `DocsDescription` and `DocsBody`, with the generated table
of contents. `source.getPageTree()` feeds the sidebar and tabs.

The docs layout links `/fumadocs-ui.css`, a copy of Fumadocs' prebuilt stylesheet generated by
`npm run docs:css`. The application itself uses Tailwind CSS 3, while Fumadocs UI 16 targets Tailwind
4; serving the prebuilt CSS as a static asset keeps the two toolchains separate. `postinstall` runs
the sync script so a fresh install has the file. `pretypecheck` and `prebuild` run
`fumadocs-mdx` so the generated `.source` collection exists before TypeScript or Next.js runs.

The application root already provides `next-themes`, so the docs `RootProvider` sets
`theme={{ enabled: false }}` and only adds the search provider. The root layout's class-based dark
mode continues to apply.

Because the application's Tailwind 3 utilities and preflight can load after the prebuilt Fumadocs
stylesheet, `docs.css` explicitly hides the desktop table of contents below the `xl` breakpoint and
restores the Fumadocs prose rhythm (heading sizes and paragraph, list, table and blockquote spacing)
under `#nd-docs-layout`. The mobile table-of-contents popover remains available.

## Content conventions

Frontmatter:

```mdx
---
title: Page title
description: One-sentence summary used by search and metadata.
---
```

- Use English (UK) spelling and `31 Oct 2026` / 24-hour times.
- Keep headings short; the TOC uses `##` and `###`.
- Use `<Callout>`, `<Cards>` and `<Card>` from the Fumadocs component set.
- Cross-link by absolute docs path, for example `/docs/user/guide/payments`.
- Screenshots live in `public/docs/screenshots/` and use the `.docs-shot` wrapper.

## Search

`createFromSource(source)` builds the search index from page titles, descriptions and structured
content. The UI calls `/docs/api/search` (configured in the layout). Search runs in the same Next.js
process; there is no external search service.

## Adding a page

1. Add an `.mdx` file under the right folder in `content/docs`.
2. Add the file name (without extension) to that folder's `meta.json` `pages` array.
3. Add frontmatter and cross-links.
4. Run `npm run typecheck` and `npm run build`.
5. Open `/docs/<path>` and check the sidebar, TOC and search.

## Verifying

```bash
npm run typecheck
npm run build
npm run dev
# open http://localhost:3000/docs
```

The docs page is part of the normal Next.js build, so a broken MDX import or missing component fails
the build rather than only the docs route. `tests/docs.test.ts` also checks the content tree,
navigation metadata, internal links and screenshot references in the unit suite.

## Deployment notes

- The docs route is public by design; do not put internal secrets or customer data in content.
- The docs CSS is loaded only on the docs segment, but Next may retain styles during client
  navigation. The prebuilt Fumadocs reset is compatible with the app's own Tailwind preflight.
- The docs search index is generated at build/runtime from the content; it duplicates no customer
  data.
